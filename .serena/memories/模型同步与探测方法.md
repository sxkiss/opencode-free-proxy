# opencode-free-proxy：免费模型同步

## 关键事实
- 可用免费模型列表**硬编码**在 `server.mjs` 的 `MODELS` 数组（约第 69 行），`/v1/models` 只回吐静态列表，不自动发现新模型。MODELS 为启动时常量，改完必须让进程重新加载源码。
- **部署生效方式（重要）**：`docker-compose.yml` 只挂载了 `api-keys.json` 与 `data`，**源码 `server.mjs` 未挂卷**，容器跑的是 build 镜像时 `COPY . .` 进去的快照。因此 **`docker restart` 不会让改动生效**，必须 `docker compose up -d --build`（重建镜像 + 重建容器）才能真正落地。验证方法：`docker exec opencode-proxy grep -A3 "const MODELS" /app/server.mjs` 比对容器内代码，再 `curl 127.0.0.1:6446/v1/models` 确认。
- 真正"免费模型"权威来源是 opencode.ai 的 Zen 免费层，实时清单接口：`GET https://opencode.ai/zen/v1/models`（需头 `Authorization: Bearer public` + `x-opencode-client: cli` + `x-opencode-project: global` + UA `opencode/1.15.0 ...`）。
- 本地出网走代理：`HTTP_PROXY=http://127.0.0.1:7890`（curl 需 `-x` 该代理；探测脚本用 `https-proxy-agent` 走 `http://127.0.0.1:7890`）。
- **探测脚本要点**：用 Node + `https-proxy-agent` 打 `https://opencode.ai/zen/v1/chat/completions`（请求头完全还原 `zenRequest`：Host/SNI=opencode.ai、`Authorization: Bearer public`、UA、x-opencode-client/-project/-request/-session）。`https-proxy-agent` 在项目 `node_modules` 里，脚本放 `/tmp` 时需 `NODE_PATH=/home/sxkiss/opencode-free-proxy/node_modules node xxx.cjs`。超时设 60s（慢模型如 nemotron-3-ultra-free 可能 30s+）。
- 上游 GitHub 仓库通常只做 `yml` 配置提交，模型新增不体现在上游 commit，必须直接探测 Zen API。

## 探测方法（核查新模型）
1. `curl -x http://127.0.0.1:7890 … https://opencode.ai/zen/v1/models` 拿全量清单（含付费；免费模型多为 `-free` 后缀，但 `big-pickle` 无后缀也是免费）。
2. 对候选 `-free` 模型发最小 `chat/completions` 验证是否真能在免费层调用（新列出者也可能临时报 "Model is unavailable"/"Internal server error"，属上游故障，可先加入观察）。

## 2026-10-15 同步（client-fingerprint gate 修复，已提交 master + 推送 GitHub）
背景：2026-09-25 后上游把 free tier 收窄，旧 `ocId()`（base64url，含 `-`/`_`）格式不符被 403；
2026-10-14 社区再传"又改了"，实则项目自身漏了多道 gate。本次彻底复刻 opencode 真实指纹：
上游 `/inference/v1/chat/completions`（官方客户端实际端点，非 `/zen/v1`）的 client-fingerprint gate 要求：
1. `User-Agent` = `opencode/<version>` 且版本 ≥ 1.18 → 用 `opencode/latest/2.0.22/cli`
2. `x-opencode-session` = `ses_` + 12 位小写 hex + 14 位 base62，且低 12 位 counter ≤ 63
   （即 `value = ~(ts*0x1000 + counter)` 取 48 位；counter 0..63 过、64.. 拒）
3. `x-opencode-session-id` 必须等于 `x-opencode-session`
4. 请求体 `stream` 必须为 `true`（本项目对客户端非流式请求在 `zenRequestFull` 里聚合 SSE→JSON）
5. 请求体 `tools` 必须含 `bash`/`glob`/`grep`/`read` 四个（缺失则补齐）
复刻算法落在 `server.mjs` 的 `encodeIdentifier(prefix==="ses")` / `ocId()` / `withFingerprintTools()`。
- 权威参考实现：`jcleng/opencode-free-provider`（GitHub，Discussion #1 有完整逆向说明），其 `src/fingerprint.js`
  与本项目复刻一致；部署验证时 git clone 该仓库起 `node server.js`（端口 8791）可独立打通上游作交叉验证。
- 模型清单（2026-10-15 实测全部可用）：`deepseek-v4.1-flash-free, space-bunny-free, big-pickle, cat-jam-free,
  mimo-v2.6-flash-free, nemotron-3.5-lightning-free, jev-1.13-free, step-5-preview-free,
  longcat-2.5-preview-free, muse-spark-1.3-contributor-free`（MODELS 已扩到 10 个）。
- **TPS 实测（生产 6446，2026-10-15）**：DeepSeek V4.1 Flash 纯生成 226~278 tok/s、端到端 86~123 tok/s、
  TTFT 7~15s；Space Bunny TTFT ~1.2s 最快；Big Pickle 仅 ~36 tok/s 偏慢。结论：V4.1 Flash 生成速度足够快。
- 落地：`docker compose up -d --build`（必须重建镜像，restart 无效）。验证：`docker exec opencode-proxy
  grep MODELS /app/server.mjs` + `curl 127.0.0.1:6446/v1/chat/completions` 实际对话。
